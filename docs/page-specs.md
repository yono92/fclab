### 데이터 요구
- 최근 분석된 유저 5명 (DB: users 테이블 ORDER BY updated_at DESC LIMIT 5)

### 인터랙션
- 검색바 Enter 또는 버튼 클릭 → `router.push(/player/${nickname})`
- debounce 300ms (타이핑 중 불필요한 네비게이션 방지)
- 빈 닉네임 submit 시 → 입력 필드 흔들림 애니메이션 + "닉네임을 입력해주세요"
- 최근 분석 유저 카드 클릭 → 해당 유저 대시보드로 이동

### 기술
- Server Component (정적 부분) + Client Component (검색바)
- 최근 유저 목록은 ISR (revalidate: 60)

## 2. 유저 대시보드 (`/player/[nickname]`)

### 목적
유저의 플레이를 통계적으로 분석하여 "나는 어떤 플레이어인지, 뭘 바꾸면 좋은지" 답변.

### URL 구조
- `/player/홍길동` → 기본 (공식경기, 최근 20경기)
- 매치타입/경기수는 쿼리 파라미터: `?matchtype=50&limit=20`

### 섹션별 상세

#### 섹션 A: 헤더
```
닉네임 (Lv.32)                    [공식경기 ▼] [최근 20경기 ▼]
```
- 닉네임: `UserBasic.nickname`
- 레벨: `UserBasic.level`
- 매치타입 셀렉터: 공식경기(50), 감독모드(52) 등 (meta_match_types)
- 경기수 셀렉터: 10, 20, 50, 100

#### 섹션 B: 신뢰도 배지 (TrustBadge)
```
📊 20경기 · 공식경기 · 3/15~4/01 · 갱신 4/02 13:00
██████████░░ 충분
```

#### 섹션 C: 종합 요약
```
┌─────────────────────────────────┬─────────────────────────┐
│     [도넛 차트]                  │ 역대 최고 등급            │
│   13승 3무 4패                   │ 🏆 챔피언스              │
│    승률 65%                      │ 공식경기 기준             │
│                                  │                         │
│  평균 점유율: 52.3%              │ 플레이 스타일             │
│  경기당 골: 1.8                  │ [5축 미니 레이더]         │
│  경기당 유효슛: 3.2              │ "빌드업형" (78/100)       │
└─────────────────────────────────┴─────────────────────────┘
```

데이터:
- 승/무/패: `match_user_stats` WHERE ouid AND match_result GROUP BY
- 역대 최고: `user_max_divisions` WHERE ouid
- 플레이 스타일: `classifyPlayStyle()` 결과

#### 섹션 D: 분석 탭

**탭 1: 슈팅**
| 위치 | 컴포넌트 | 데이터 |
|------|---------|--------|
| 좌측 | ShootingHeatmap | match_shoot_details WHERE ouid |
| 우측 | PercentileGauge × 5 | 유효슈팅률, 골전환율, 박스내비율, 헤딩골비율, PK성공률 |
| 하단 | 존별 분석 테이블 | shoot_details를 6구역으로 분류 집계 |

계산 공식:
```
유효슈팅률 = SUM(effective_shoot_total) / SUM(shoot_total) × 100
골전환율 = SUM(goal_total) / SUM(shoot_total) × 100
박스내비율 = SUM(shoot_in_penalty) / SUM(shoot_total) × 100
헤딩골비율 = SUM(goal_heading) / SUM(goal_total) × 100
PK성공률 = SUM(goal_penalty_kick) / SUM(shoot_penalty_kick) × 100
```

**탭 2: 패스**
| 위치 | 컴포넌트 | 데이터 |
|------|---------|--------|
| 좌측 | 도넛 차트 (PassDistribution) | 숏/롱/스루/로빙/그라운더 비율 |
| 우측 | PercentileGauge × 5 | 전체/숏/롱/스루/로빙 성공률 |
| 하단 | 빌드업 성향 텍스트 분석 | 규칙 기반 문장 생성 |

계산 공식:
```
전체 패스 성공률 = SUM(pass_success) / SUM(pass_try) × 100
숏패스 비율 = SUM(short_pass_try) / SUM(pass_try) × 100
(각 유형 동일 패턴)
```

**탭 3: 수비**
| 위치 | 컴포넌트 | 데이터 |
|------|---------|--------|
| 좌측 | PercentileGauge × 5 | 태클성공률, 블록성공률, 파울, 옐로, 레드 |
| 우측 | ConcededTimeHistogram | 상대 shoot_details의 goalTime 분포 |

실점 시간대 계산:
```sql
-- 상대의 골 시간을 15분 구간으로 분류
SELECT (goal_time / 900) * 15 as bucket, COUNT(*) as goals
FROM match_shoot_details
WHERE match_id IN (내 매치들) AND ouid != :myOuid AND result = 1
GROUP BY bucket ORDER BY bucket;
```

**탭 4: 선수**
| 위치 | 컴포넌트 | 데이터 |
|------|---------|--------|
| 전체 | 테이블 | match_player_stats 집계 → TOP 10 |

```sql
SELECT sp_id, 
  COUNT(*) as appearances,
  AVG(goal) as avg_goal,
  AVG(assist) as avg_assist,
  AVG(sp_rating) as avg_rating
FROM match_player_stats WHERE ouid = :ouid
GROUP BY sp_id ORDER BY appearances DESC LIMIT 10;
```

선수명: `meta_players` JOIN으로 해결.
포지션: `meta_positions` JOIN.
시즌 아이콘: `spId / 1000000` → seasonId → `meta_seasons.seasonImg`.

## 4. 나 vs 랭커 비교 (`/player/[nickname]/compare`) — Phase 2

### 목적
내 선수별 스탯을 랭커 평균과 직접 비교. "뭐가 부족한지" 명확히 보여줌.

### 핵심 데이터 흐름
```
1. 내 주요 사용 선수 TOP 10 (match_player_stats 집계)
2. 각 선수의 랭커 평균 스탯 (ranker_stats WHERE sp_id AND sp_position)
3. 차이 계산 + 효과 크기(Cohen's d)로 유의미한 차이 판별
```

### 선수별 비교 카드
```
메시 (TOTY) — ST — 18경기 출전

[레이더 차트: 나(실선) vs 랭커(점선)]

│ 지표       │ 나    │ 랭커  │ 차이   │ 효과크기 │ 판정    │
│ 경기당 골  │ 0.8   │ 1.2  │ -0.4  │ d=0.8   │ ⚠ 큰차이│
│ 유효슈팅률 │ 55%   │ 68%  │ -13%p │ d=1.1   │ ⚠ 큰차이│
│ 패스성공률 │ 89%   │ 85%  │ +4%p  │ d=0.3   │ ✅ 유사 │
│ 평점       │ 6.8   │ 7.4  │ -0.6  │ d=0.6   │ ⚠ 차이  │

💡 가장 개선 필요: 유효슈팅률 (효과 크기 1.1 — 매우 큰 차이)
```

### 효과 크기 판정 기준
- |d| < 0.2: "✅ 유사" (차이 무시 가능)
- 0.2 ≤ |d| < 0.5: "⚡ 약간 차이"
- 0.5 ≤ |d| < 0.8: "⚠ 차이"
- |d| ≥ 0.8: "⚠ 큰 차이"

## 5. 변화 추적 (`/player/[nickname]/trend`) — Phase 3

### 목적
"지난주보다 나아졌는가?" 답변. 재방문 동기 생성.

### 핵심 조건
- 최소 2회 이상 검색 기록이 있어야 의미 있음
- 첫 방문 시: "다음에 다시 검색하면 변화를 추적할 수 있습니다"

### 데이터
- 검색할 때마다 `match_user_stats`에 시계열 데이터 축적
- 기간별 집계: `v_user_recent_stats`를 기간 필터로 2번 호출

### 차트
- 승률 가중이동평균 라인 차트 (weightedMovingAverage)
- 핵심 지표 변화 테이블 (이전 vs 현재 vs 변화량)
- 트렌드 해석 텍스트 (규칙 기반)

## 6. 메타 대시보드 (`/meta`) — Phase 4

### 목적
현재 메타를 랭커와 일반 유저로 분리해서 보여줌.

### 핵심 차별화
다른 사이트는 랭커 메타 = 전체 메타로 취급. FCLab은 분리.

### 데이터
```sql
-- 랭커 메타: ranker_stats 집계
-- 일반 유저 메타: match_player_stats 집계

-- 포지션별 인기 선수 (랭커)
SELECT sp_id, sp_position, COUNT(*) as usage
FROM ranker_stats
WHERE match_type = 50
GROUP BY sp_id, sp_position
ORDER BY usage DESC;

-- 포지션별 인기 선수 (일반)
SELECT sp_id, sp_position, COUNT(DISTINCT match_id) as usage
FROM match_player_stats
WHERE match_id IN (SELECT match_id FROM matches WHERE match_type = 50)
GROUP BY sp_id, sp_position
ORDER BY usage DESC;
```
